# EC 工单系统需求清单（最新原型版）

**版本**：2026-09-19 v1.1（原需求与当前原型对照更新）  
**原型来源**：`ui-prototype/index.html`  
**代码基线**：本地 `main / 2e06126`（2026-09-18）；本次未重新拉取 GitHub  
**文档定位**：用于客户评审、范围确认、POC 拆分和后续开发排期。  

> 本清单描述的是最新静态 UI 原型能力，不等同于已完成生产系统。原型当前使用前端模拟数据，不连接真实后端、数据库、消息渠道或财务接口；所有“可演示”功能仍需经过范围确认、POC、真实数据、权限和验收。

本次保留 F001—F072 编号，补充 F073—F080，共 **80 项需求**。第 2 节按业务模块查阅，第 7 节集中列出原需求与原型的差异。表内“范围建议”是评审建议，不代表客户已经确认；原文档中的 P2 表示一期仅预留字段，本清单的 P1/P2 表示功能需另行评估，不能直接用作合同阶段划分。

- 补回原需求中的自动编号、不可拍照豁免、工单池、报销关联、项目编号和归档要求。

## 3. 关键业务规则

### 3.1 分派规则

1. 分派中心使用独立“任务编号”，不替代 CALL 编号，也不在 CALL 编号上附加派工后缀。
2. 当前原型推荐限定同区域、启用且可接单的师傅，并取当前负载最低者；技能只供人工筛选参考，不参与自动匹配。同区无候选人时不跨区推荐。
3. 请假师傅必须置灰且不可分派；原型以待确认/待处理/处理中工单数计算负载，负载 ≥ 3 标记忙碌。请假目前是静态模拟，日期到期判断、真实考勤接入和生产阈值均须确认。
4. 当前原型的 TL 按本人负责的工单限制可见范围，CR 按本人区域限制；TL、CR、ADMIN 显示分派操作。生产权限需逐单校验，页面入口限制不等于后端数据安全。
5. 有领料记录、采购关联、物料明细或关联报价时自动判定完工单，否则纯 CALL 走服务报告；分派端和师傅端不手动选择。上述规则来自原型代码，客户仍需用真实样例确认。
6. 原型 CALL 编号为 `WO-YYYYMMDD-NNN` 或政府前缀格式；任务编号为 `T-YYMMDD-NNN`。正式编号须处理业务时区、多人并发、历史数据和唯一约束。

### 3.2 报价、标书和采购规则

1. 报价、标书、采购均与 CALL/客户/项目关联，但是否纳入一期必须单独确认。
2. 报价中的成本价和供应商信息仅作为参考，不代表库存锁定或真实供应商接口已经完成。
3. 采购验收完成后是否自动创建待分派工单，由客户确认启用范围、编号规则和责任人。
4. 标书管理由 TENDER 标书组负责；QUO 报价组默认不显示标书管理入口。
5. 报价已中单自动建立备货单，重复触发不重复创建；一张备货单可挂多张采购单，采购单由采购部手工创建与维护，不是自动生成全部 PO。
6. 原型报价主状态为待报价、报价中、已中单、丢单；标书主状态为待投标、不投标、已中标、未中标。须与业务方统一状态定义及联动条件。

### 3.3 移动端规则

1. 师傅端只展示本人任务和必要现场信息，不进入复杂后台配置。
2. 现场流程包含检查/到场、处理记录、照片/附件、完工提交等步骤；页面支持暂存。
3. 不可拍照客户可免除照片强制项，但必须填写文字说明或替代证明。
4. 弱网/离线能力、OCR、真实图片上传和电子签名必须经过真机 POC。

## 4. 一期建议范围

建议一期聚焦可闭环交付：

- 首页待办、CALL 建单与查询、分派/改派、师傅移动处理、SR/CP 报告管理。
- 用户、客户、地点、区域、CALL 类型和状态字典等基础设置。
- 基础统计、待办提醒、操作日志和必要的权限矩阵。

报价、标书、备货、会计和 Peachtree 接口建议作为 P1/P2 单独确认，不因原型可演示而自动承诺为一期生产功能。

## 一、全局流程總覽（三線同構骨架）

```
觸發入口
 ├─ 工單: CS 來電→判斷→建單/即時解決        (CS Call)
 ├─ 標書: 主動尋找/被動接收→匯入掃描→自動分配→回標→中標
 └─ 報價: 收到報價請求(報價組/CR)→新建報價單→三態庫存判定→發出→客人確認
                    ↓
        類別三叉 (關鍵節點)
         ├─ M 保養   → By 1-8區組   → 執行角色 CR
         ├─ P 工程   → By Project組 → 執行角色 Project主管
         └─ M+P     → By ?組       → 執行角色 ?主管 (待確認)
                    ↓ 系統通知相屬主管(+CR，M線多通知CR)
        聯絡客人預約現場勘測
         ↓ 兩條並行
   建立MR物料申請單→查庫存   ∥   分派任務PM排程→師傅收到通知
   ↓
  備貨: 查庫存→有存貨[申請貨品→倉務確認→留貨] | 無存貨[向採購部申請→PO→收貨→
       已收貨通知(倉務+主管)→入庫存] → 確認貨品數量→核對→
       全部正確[準備貨品+列印完工紙→合併放倉庫→分派師傅] | 錯誤[通知採購倉務→回流]
   ↓
  現場執行(師傅側):
   待確認→收到→待處理 → 準時到達簽到→處理中 | 未能準時→超時通知
   (團隊工單: 申請接單→需要審批→通過進待處理/不通過通知主管)
   ↓ 開始保養檢查 → 能否即時處理?
     ├─ 能: 拍照(未維修)→維修→拍照(已維修)→客戶確認簽名蓋印→掃描完工紙→完成
     │      → 狀態已完成 + 通知(主管+會計部)
     └─ 不能: 填寫服務報告進行報價→客戶簽名→掃描提交→系統更新+通知(報價部+採購部)
            → 報價組收→填報價表(三態庫存判定)
   ↓
  後補報價: 後補補價→確認/編輯掃描資料/語音輸入→通知(報價部+主管)→
           報價部收到→發出報價+完工紙給客戶→客戶回覆確認
   ↓
  財務閉環: 客戶確認→報價組轉發會計部開發票→收款→流程完結
```

### 各流程獨有規則

| 流程 | 獨有節點 |
|---|---|
| **CS Call** | 來電判斷→CS可處理(勾選已解決更新工單)/未能處理(投訴→通知CR 或 建來電單→自動轉工單→通知Super→分配) |
| **PM** | 管理層用戶發單→狀態含「已接單」→接單/不接單(填原因)→開始檢查→即時維修判定 |
| **Special(應急)** | 5分鐘無接單→通知(發起人+Super)；5分鐘未簽到→通知；報價資料、**實體/電子完工紙**、交通費用、備註 |
| **CM** | PM員工收CM通知→接受CM(放棄PM排程)/不接受(繼續PM)→CR/CS/Super重新分配 |
| **報價 vs 標書** | 報價多「報價單生成」（三態庫存判定）與「財務閉環」；入口4個 vs 2個；標書庫存二態 |

### 三線同構對照（M/P/MP 僅角色不同）

| 節點 | M線 | P線 | MP線 |
|---|---|---|---|
| 勘測/MR/查庫存/申請貨品/確認數量/準備完工紙 | CR | Project主管 | ?主管 |
| 團隊審批 | 需CR/主管審批 | 需Project主管審批 | 需CR/主管審批 |
| 完成通知 | CR+會計部 | Project主管+會計部 | ?+會計部 |

## 二、原型 vs 流程文件：一致性核對報告

**總體結論**：原型已覆蓋流程文件約 **60%** 核心環節（建單→派單→師傅執行→服務報告/完工紙→報價→採購→財務），主鏈路通。存在 **6 類結構性缺口**：① 狀態機簡化（無「已接單/待審批」→已補待審批）；② 三態庫存判定完全缺失；③ M/P/MP 類別三叉未接通知；④ 物料申請單 MR / 倉務確認 / 留貨環節缺失；⑤ 後補報價閉環缺失；⑥ 通知系統未接線（已大幅改善）。

### 2.1 工單主流程（CS Call / PM / 現場執行）

| 流程節點 | 狀態 | 備註 |
|---|---|---|
| CS 來電判斷（需要建單/僅答疑） | ✅ | `renderCreate` 來電判斷下拉 |
| CS 即時解決（勾選已解決） | ⚠️ 簡化 | prompt 輸入原因直接關單 |
| 來電單→自動轉工單 | ⚠️ 差異 | 無獨立「來電單」實體 |
| 通知維修/工程部門 Super | ❌ | CS 建單不通知 TL/Super |
| 投訴→通知 CR | ⚠️ 部分 | 僅 `saveWorkOrder` 彈窗路徑觸發 |
| 師傅收到→待確認→收到→待處理→簽到→處理中 | ✅ | 移動端三步流程 |
| 申請接單→審批（團隊工單） | ✅ | **本次新增**：待審批狀態 + 通過/不通過 |
| 拒單（必填原因） | ✅ | **本次新增**：回待分派 + 通知 TL/CS |
| 改派（重新分派） | ✅ | **本次修復**：原彈窗限制 `待分派` 狀態 |
| 超時提醒（5分鐘無接單/未簽到/即將超時） | ✅ | **本次新增**：`checkTimeouts` + 模擬超時演示 |
| 退回補充 | ⚠️ 部分 | 僅確認不通過退回師傅繼續處理 |
| GPS 定位 | ❌ | 簽到僅時間戳，無座標 |

**狀態機**：`待分派/待確認/待處理/處理中/待審批/已完成/已取消`（待審批為本次新增）。

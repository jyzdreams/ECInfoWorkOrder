# EC 工单业务流程图册依据与主链路记录

日期：2026-09-26；状态：草案 / 待确认。

## 本轮用户明确说明

- 报价、必要时修订、客户确认中单、仓库备货、派工、现场处理、客户确认、提交 SR/完工单，是当前讨论的一条主要业务链路，不等于全项目唯一入口。
- 备货由外部系统「仓库通」处理，并向 EC 工单系统同步状态。图中不得将 EC 的状态展示画成由 EC 手工推进仓库执行状态。
- 用户明确表示流程仍有问题。记住主链路不等于批准所有分支、状态、接口或范围。

## 来源及适用优先级

1. 本轮对话中的用户说明，优先于旧资料中的仓库归属冲突。
2. `outputs/019fb6ef-a630-7810-adc9-c8fd4cb24432/02-SOP流程图/纯SOP版/` 三张已提取 SOP 流程图。
3. `.codex/sop-alignment/sop-graph.json`、`sop-components.md`：SOP.jam 的既有结构化提取结果。本轮不宣称重新完整解析原始 .jam。
4. `knowledge-base/data/knowledge-base.json`：沿用 FLOW-001 至 FLOW-012 流程组编号；其中旧状态不自动提升为客户批准。
5. `docs/08-sop-prototype-requirements-alignment-audit.md`、`knowledge-base/OPEN_QUESTIONS.md`：保留完工、接单、编号、通知、接口等未决项。
6. `docs/07-complete-workflow.md`：补充修订、后补报价、拒单、财务等历史场景；与较新说明冲突时不据此定稿。

本轮为业务流程可视化，不代表当前 prototype 已能执行全部闭环，也不改变原型源码。

## 本轮不擅自定稿的事项

| 编号 | 事项 | 图中处理 |
| --- | --- | --- |
| AT-Q01 | MR 在哪套系统创建、如何提交仓库通 | 使用“交接 MR/物料需求”，标明入口和方式待确认，不承诺双向自动接口 |
| AT-Q02 | 具体回传状态、状态含义、频率及匹配单号 | 已确定方向为仓库通到 EC；具体值只作草案说明 |
| AT-Q03 | 备齐后是否一律才能派工 | 主链路按备齐并核对后安排施工；部分到货/无需物料能否先派待确认 |
| AT-Q04 | 后续施工恢复原工单还是新建关联工单 | 两者列为待决策，不固定新建时点和编号后缀 |
| AT-Q05 | 师傅提交后直接完成还是主管审核 | 图中作为互斥候选，不能同时视为必经步骤 |
| AT-Q06 | 报价、中单、工单、备货状态 | 分对象看业务里程碑，不新增统一状态枚举作为开发结论 |
| AT-Q07 | Project/CR/TL/CS 分派权限及混合业务负责人 | 保留 SOP 称谓和职责差异，未明确处标记待确认 |
| AT-Q08 | 开票时点、分期开票、会计接口 | 作为独立商务分支；收款完成不是所有工单完成的强制前提 |
| AT-Q09 | 不可拍照、签名缺失、多 SR、返工 | 来源存在的例外保留，豁免权限及最终完成条件待确认 |
| AT-Q10 | 后补报价已完成现场工作 | 不自动再进入备货施工；仅存在新增施工需求时再走该分支 |

## 阅读与验收口径

- 实线表示本图业务推进，虚线表示跨系统回传、补充通知或待确认方案。
- 角色泳道用于确认谁做什么；节点上的 FLOW 编号对应本图册及知识库流程组，不冒用 F 功能编号。
- 每图给出来源、关键单据/里程碑、待确认项和下一流程。
- 总览能定位所有 12 个流程组；每张分图能看到入口、分支、结果和跨图去向。
- 本轮验证仅验证图册布局、文件可打开、连线/节点引用与追溯，不是原型走查或业务验收。

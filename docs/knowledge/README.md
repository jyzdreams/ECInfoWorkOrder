## 事实与批准

- L1：客户原始资料、明确表达或身份/日期/结论可追溯的确认结果。
- L2：多个L1共同支持的稳定整理规则，保留原始引用。
- L3：项目整理/工作决定，尚无明确客户确认出处的部分。
- L4：原型自行设计、推测或找不到来源的规则。

客户原始资料优先；用户业务决定记录身份和范围；PRD、原型、代码不能反向证明客户事实。工作决定不等于80项功能批准，客户需求确认不等于原型走查通过。

## 三个入口怎样维护

| 变化 | 写入位置 |
| --- | --- |
| 新客户资料 | 保留原件，来源索引登记路径/身份/整合状态 |
| 业务决定/纠正/冲突 | 对应知识详情记录出处、日期、影响和旧结论，总览定位，不复制全文 |
| 任务/范围/责任/依赖/阻塞/验收 | 内部推进主台账，不增加平行Markdown/JSON任务进度 |
| 有明确依据的页面/交互 | 当前prototype/，关联主台账需求/任务与决定 |
| 客户确认材料 | 按主台账稳定编号/版本导出，反馈复核后回填，保存原确认依据 |
| 审计/回归证据 | 对应证据目录保留版本，主台账引用，不改写旧PASS |

知识详情是这个知识库的下钻内容，不要求每天逐份修改；仅在对应规则变化时更新拥有它的文件，不新建同内容PRD/Flow/看板。

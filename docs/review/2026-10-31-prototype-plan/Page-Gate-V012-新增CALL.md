## 1. 页面定位：新增CALL到底是什么

新增CALL是**CS记录客户问题／服务请求，明确客户与合同上下文，并选择负责主管的受理入口**。主管随后判断自行解决、需要报价或需要安排师傅上门。它不是每条业务的统一起点，也不是一按提交就批准施工的入口。

| 业务问题 | 当前Hub能够确定的答案 | 不能扩展的边界 |
|---|---|---|
| 谁创建 | CS有建立CALL、检索合同、选择主管的依据。 | CR/TL/其他角色是否也能从本入口创建，以及跨区资料权限，不能从原型有按钮推定；本轮只用CS验证。 |
| 什么情况下创建 | 收到真实客户问题／需求，需要记录、交主管处理；同合同已有CALL也可新增另一笔真实需求。 | 不新设“相似未关闭CALL自动合并／禁止新增”等规则；自主询价、正常M保养不因此强制补CALL。 |
| CALL代表什么 | 客户服务受理与分流记录，保留问题、实际创建／选择主管／后续处理过程及来源关系。 | 客户咨询、进度查询、投诉并非必定变成维修成交。 |
| CALL是不是工单 | 在口语／旧原型中可能称“工单”；当前业务对象需区分**CALL受理记录**与**师傅执行的工作工单／任务**。 | 不因为同名就把两种生命周期合并；也不据此决定必须新增数据库表或更换技术ID。 |
| 是不是现场任务 | 不是。只有主管判断需上门，才进入安排／派师傅的业务接口。 | 任务具体创建时点、数量关系、自动生成和编号仍属C-07/C-11/C-09。 |
| 与P/M/M+P的关系 | CALL属于来源／取得维度；P/M/M+P属于履约分类。 | 没有“每笔CALL创建时必须由CS选择P/M/M+P”的当前明确规则；不从CALL类别或紧急程度自动推断核心分类。 |
| 与报价的关系 | 主管判断需报价后，关联需求进入报价组公共待办，实际接手人负责报价。 | 创建CALL不等于正式报价、客户接受或中单；不在V012选择具体报价员。 |
| 与客户／合同的关系 | 一客户可有多合同、一合同只属一客户；客户名可重复。以“合同编号＋客户名称”查询并选择明确合同，保存后可追溯。 | Hub没有要求固定“先客户、后合同”两步操作，也没有决定数据库主键／全表外键。 |
| 创建后交给谁 | 本笔CALL所选负责主管。 | 跨区候选可选不等于获得全区域数据读写权限；通知渠道／时限／已送达凭据未在本页定案。 |
| 完成后可能去哪 | 留在受理上下文供主管处理；业务上可能自行解决、转报价公共待办、转上门安排。 | 三方向不是已批准的三状态；不是本页提交后的三个自动跳转。具体关闭／重开规则仍待C-02。 |

## 5. 客户／合同专项结论

### 当前原型

1. 通常先选政府／私人，之后从客户下拉选择；已有增强组件支持输入关键词。
2. 候选按`customerId`选择，不是把用户输入名称直接当ID。V012保存使用`customers.find(c.id===customerId)`；**本页未发现“按名称取第一条客户”的具体操作**，旧PV-002不能直接套到本页。
3. `customerSub()`优先读`contractNo`；政府历史数据fallback为`合約編號 contractNumber`。实测政府输入`0471`，能找到“香港政府大樓／合約編號0471667”。当前默认私人样例无合同副标题，不能声称所有客户候选都有合同号。
4. 客户变化带出首地址区域、首联系人／电话及地址，主管候选同区且留空；政府显示Call代码／J No.。从客户预带入口初始化时，地址却为空，和手动选同客户不一致。
5. 保存ticket主要保留customerId，callLog主要保留客户文字和workOrderId；没有本次所选合同快照／引用。客户中单一contractNo的结构不能证明一客多合同已正确承载。

### Hub事实、差异及建议

**KEEP**：已有模糊搜索组件、合同副标题搜索能力、customerId绑定、已有联系人带入及可修改；不为了理论更合理重做控件，不改成固定“先客户再合同”的新交互。

**真正冲突**：不能明确同一客户的不同合同及本次选择，且保存上下文不完整。合同号作为辅助文字出现不等于已完成合同选择／追溯。此问题需要现有资料关系和跨页消费方共同核定，归**L3 HOLD**，不是把标签“客户”改成“合同”就算完成。

**不采用旧计划的自动方案**：本轮不批准新建Contract模型、CALL受理新集合、用重复客户伪装多合同、自动选首合同、批量猜旧数据、自由输入一个合同号后当作真实关联，也不新增客户／合同维护入口。未来若有现成可靠合同数据、可在原控件表达，再评估是否能降为局部L2，当前不预判。

已明确的“一客多约、一约一客、名称可重复、合同＋客户组合查询”不再向客户重复提问；需确认的是未覆盖场景与落地边界。

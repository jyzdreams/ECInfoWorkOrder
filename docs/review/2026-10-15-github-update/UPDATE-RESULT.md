## 3. 采用的内容及依据

已有[业务基线§1.5](../../knowledge/03-business/EC-REAL-BUSINESS-BASELINE.md#15-maintenance-plan--整期保养计划)和[讨论决定CONFIRMED-011/012/013](../../knowledge/decisions/DEC-20260927-真实业务流程讨论.md)明确：报价阶段区分M/P/M+P，含M报价确定保养周期，中单后生成整期计划；M和P分别推进，没有固定先后。原型原有`createMaintenancePlan`已实现此规则。本轮补展示和保存衔接，不新增业务决定。

| 内容 | 最终接入方式 |
| --- | --- |
| 报价详情保养排期 | M/M+P只读展示起止日期、月份间隔、计划编号和期数；P不展示该卡 |
| 新增报价 | 新增保养排期卡，选择M/M+P时显示并启用；P隐藏且字段不进入提交数据 |
| 编辑报价 | 复用原有周期保存，只保留一套同名字段；P切换到M/M+P可填写，切回P禁用 |
| 保存合同周期 | 新建报价直接保存contractStart/contractEnd/serviceEveryMonths，编辑清空仍可回读空值，不回填旧日期 |
| 中单生成计划 | 保留原有M周期校验、成交快照和单份生成；补显式计划引用，不重复生成第二套计划 |
| CALL只读信息 | 兼容已有保养期次/排程信息展示，不创建此类数据或改变派工条件 |

远端提供1/2/3/6/12个月固定下拉，但既有输入允许正整数月份，未找到仅限这五项的依据。本地保留原数值输入与既有控件范围，4/5个月旧值可读取、保存和展示，不因更新丢失。

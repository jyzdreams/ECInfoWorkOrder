## 已确认（CONFIRMED）

### CONFIRMED-001

普通维修/工程业务主干基本确认。

### CONFIRMED-002

真实维修存在三种主要情况：先报价后维修、保养发现问题后二次维修、现场即时维修。

### CONFIRMED-003

客户接受报价并中单后，进入材料和施工准备。

### CONFIRMED-004

中单后可以先预排师傅和预计施工时间；该时间不是最终与客户确认的正式施工时间。

### CONFIRMED-005

材料准备完成后，由 CR / 主管负责与客户确认正式施工时间；CR 为客户关系部。

### CONFIRMED-006

MR 为材料申请单；系统根据成交报价中的材料信息自动生成 MR，不再由 CR 人工制作。

### CONFIRMED-007

MR 不是报价完成就生成；客户确认报价、报价组确认中单后，系统才按最终成交报价材料生成 MR。

### CONFIRMED-008

报价组负责报价完整生命周期和 R1/R2/R3 等版本历史，客户最终接受后由报价组确认中单。

### CONFIRMED-009

报价任务有四个主要入口：CS 经 CR/主管、CR 直接发起、Tender、Service Report 选择需要报价。

### CONFIRMED-010

施工完成后，客户确认/签名，师傅提交 Service Report，CR / 主管简单确认后正式完工。

### CONFIRMED-011

业务类型 M、P、M+P 在报价阶段确定；M+P 表示同一报价同时包含 M 与 P。

### CONFIRMED-012

报价包含 M 时，在报价阶段确定保养周期；中单后按保养周期和合同周期生成整期保养计划。

### CONFIRMED-013

M+P 不存在固定“P 完成后才 M”的顺序，M 与 P 可分别推进。

### CONFIRMED-014

CM 业务真实存在。

### CONFIRMED-015

CM 一般无固定插单机制；通常由 CR / 主管直接指定师傅，现场服务后提交 SR 并确认完工。

### CONFIRMED-016

Tender / 标书主要用于政府项目；中标后按业务内容进入 M、P 或 M+P。

### CONFIRMED-017

正常发票和收款主要关联报价业务；工单完工与收款完成不是同一业务状态。

## 当前真实业务流程摘要

客户需求 → CS / CR → 报价任务 → 报价组 → 报价版本沟通 → 客户确认 → 报价组中单 → 判断 M / P / M+P。

- P：中单 → 自动生成 MR → 备货/采购 → 材料完成 → CR/主管确认正式施工时间 → 师傅服务 → Service Report → CR/主管确认 → 完工。
- M：报价确定周期 → 中单 → 生成整期保养计划 → 到期排期 → 上门保养 → Service Report → CR/主管确认 → 本次保养完成。
- M+P：分别进入 M 与 P 流程，不设置固定先后顺序。
- 保养发现维修问题：Service Report 选择“需要报价” → 自动生成报价任务 → 再进入报价链路。
